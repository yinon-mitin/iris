# Эксплуатация

[English](../OPERATIONS.md) · [Русский](OPERATIONS.md)

Повседневная работа с установленным ботом. Первая установка описана в [Установке](INSTALL.md).

## Команды

| Команда | Что делает |
| --- | --- |
| `make up` | Собрать образ и запустить или обновить бота |
| `make down` | Остановить и удалить контейнер (данные в `data/` сохраняются) |
| `make restart` | Перезапустить; заодно ставится свежий yt-dlp nightly |
| `make ps` | Состояние контейнера |
| `make logs` | Журнал в реальном времени (`Ctrl+C` — перестать следить) |
| `make shell` | Shell внутри работающего контейнера |
| `make check` | Статические проверки без Docker: секреты, документация, синтаксис Python, shell, Compose |
| `make test` | `make check`, затем сборка образа и unit-тесты внутри него |

## Обновления

**yt-dlp обновляется сам.** Контейнер ставит свежую nightly-сборку при каждом запуске и проверяет обновления каждые `YTDLP_UPDATE_INTERVAL` секунд (по умолчанию раз в сутки). Если вышла новая сборка, бот сам перезапускается.

**Обновление Iris:**

```sh
make update        # git pull --ff-only, затем make up
```

Настройки, пользователи и список доступа хранятся в `data/` и `.env` и переживают обновления.

## Резервные копии

Всё, что стоит хранить, — две вещи:

```sh
tar czf iris-backup.tgz .env data/
```

Для восстановления распакуйте архив в свежий клон и выполните `make up`. Храните архив как секрет: в `.env` токен бота и ключи API.

## Проверка состояния

```sh
make ps                               # контейнер в состоянии «Up»
make logs                             # «Firewall: …», «yt-dlp version: …», «Session started»
docker compose exec bot ls /tmp      # пусто, когда нет активных задач
```

## Если что-то не работает

**Бот молчит.**
Выполните `make logs`. Проверьте, что ваш ID указан в `OWNER` или `AUTHORIZED_USER` и в нём только цифры.

**Контейнер завершается с «Firewall setup failed».**
У контейнера нет права `NET_ADMIN`. Сохраните блок `cap_add: [NET_ADMIN]` в `docker-compose.yml`. В некоторых rootless- или ограниченных установках Docker это право недоступно; бот намеренно не запускается без фильтра.

**«Эта ссылка ведёт во внутреннюю сеть».**
Ссылка указывает на частный адрес или на домен, который в него разрешается. Так задумано, и из чата это не отключить; см. [Архитектуру](ARCHITECTURE.md#фильтр-исходящих-соединений).

**«Видео слишком большое».**
Telegram принимает файлы до 2 ГБ. Выберите в `/settings` качество «Среднее» или «Экономное».

**Перестал скачивать какой-то сайт.**
Обычно сайт что-то поменял, а yt-dlp ещё не обновился. Выполните `make restart`: при запуске ставится свежий nightly. Если не помогло, поищите проблему в [issues yt-dlp](https://github.com/yt-dlp/yt-dlp/issues).

**YouTube или Reddit просят войти в аккаунт.**
Добавьте cookies, как описано в [Установке](INSTALL.md#6-все-настройки-env).

**`docker-credential-osxkeychain: executable file not found` (macOS + OrbStack, сборка по SSH).**
В SSH-сессии нет пути к утилитам OrbStack:

```sh
export PATH="$HOME/.orbstack/bin:$PATH"
```

**После перезагрузки компьютера бот не запустился.**
Включите автозапуск OrbStack или Docker Desktop при входе в систему; контейнер перезапускается сам.

## Изменения из оригинального ytdlbot

Iris развивается самостоятельно, но исправления из оригинального проекта можно влить вручную:

```sh
git remote add upstream https://github.com/tgbot-collection/ytdlbot.git   # один раз
git fetch upstream
git merge upstream/master
make test && make up
```

Ждите конфликтов в `src/main.py`, `src/engine/` и `src/config/constant.py`: в Iris они сильно изменены.
